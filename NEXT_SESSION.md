## G25: Option, кандидат исправления (23.10.2026)

- Пользователь: курсор в конце без выделения, Option не меняет слово и
  показывает общий unavailable notice; проблема есть и в других приложениях.
  Разрешения в настройках включены, но собственный AX trust процесса этим
  не доказан. Реальная причина постоянного отказа пока не установлена.
- Production EventTap → KeyTranslator → Engine → SelectionConverter/Target
  на собственных невидимых NSTextView воспроизвёл отказ свежего поля при
  устаревшем кеше предыдущего. Снимок текущего поля теперь принимается с
  отменой старых permits/undo; sampler не перезаписывает ожидающий захват.
  Ввод, клик, смена поля/PID/каретки по-прежнему отменяют операцию.
- Второй RED: изменение контекста перед словом во время AX-чтения не отменяло
  Option. Полный снимок теперь проверяется до записи для fallback, выделения
  и штатного буферного слова/undo. Уведомление различает trust/secure/field/
  range/text/changed без текстового лога. Bootstrap допускает замену
  не редактируемого wrapper на поле, но не переход между двумя полями.
- `MLS_OPTION_ONLY=1 bash tools/test-keyboard-engine.sh` запускает Option
  случаи; обычный runner также запускает прежние autorepeat/recovery случаи.
  `MLS_ENGINE_SOURCE_ROOT=/path/to/baseline` подставляет всю production-базу.
  Sandbox: задавать CLANG_MODULE_CACHE_PATH и SWIFT_MODULECACHE_PATH в /tmp.
- Это локальные AppKit/system-boundary проверки, не физическая приёмка
  Codex/всех приложений. CUA запретил com.openai.codex; обход через AX, shell,
  CDP или другой инструмент запрещён. Проверка реального редактора — вручную
  пользователем. Root ведёт финальные ревью, release и статус в G25 spec/QA.

## G23 / 1.4.6: исправление диктовки, финальный код одобрен (10.10.2026)

- На установленной 1.4.5 пользователь получил только `Давай проверим,` при
  полном распознанном результате `Давай проверим, работает ли вставка.`.
  Это отдельная ошибка диктовки; аппаратный Space G22 её не проверяет.
- Тот же `tools/test-dictation-completion.sh` на базе `438c8be` дал literal
  RED: `Давай проверим, `, одна порция, каретка 16, fallback unconfirmed.
  Повторное собственное AX selection notification отменяло permit, который
  ожидал ровно одно уведомление на порцию. Факт таких уведомлений в реальном
  Codex пока не доказан.
- Реализация 1.4.6 проверяет уведомления по точному полю/значению/диапазону текущей
  записи. Раздельная публикация value/caret ожидается ограниченно только для
  известных состояний этой записи; после подтверждения новые проверки используют
  итоговое состояние. Physical input/focus и замеченное чужое изменение
  отменяют право вставки навсегда. Запись не повторяется; полный результат
  при неопределённости остаётся в прежней selectable recovery панели.
- Новый runner дал GREEN полного текста/каретки, Unicode и абзацев, замены
  выделения с сохранением соседей, duplicate/coalesced/late уведомлений,
  delayed value/caret, sticky cancellation и no-op/partial без retry.
  Оба независимых ревью нашли гонку первого кандидата: уже прочитанное чужое
  AX-состояние терялось при confirmWrite. Новый immutable snapshot устраняет
  это: сохранённые foreign value/range дают sticky cancel, старый/новый
  собственный снимок через границу порций даёт полную once-only вставку.
  `notification-race.swift` сохраняет независимое воспроизведение Standards;
  completion runner автоматически запускает четыре конкурентных случая.
  Следующее Spec-ревью воспроизвело усечение длинной фразы: callback начал
  чтение на порции 1, сохранил собственный снимок порции 2, завершился на 4.
  Теперь известные состояния сохраняются только на время активного чтения AX;
  список ограничен 16 наборами, при заполнении worker ждёт до 0,6 с. Ввод/
  focus отменяет ожидание сразу; конец чтения/отмена очищает список. Новые
  multi-own регрессии дают полный результат 108/432 UTF16, bounded refusal
  при зависшем AX, отмену во время ожидания и отказ по чужому восстановлению
  старого значения после окончания чтения. Все включены в обычный runner.
  После ожидания повторно проверяются точное поле, значение, каретка и permit
  перед отправкой следующей порции. Чужое значение/каретка, другое поле или
  Secure Input во время ожидания дают sticky cancel без следующей записи.
  Финальный completion runner включает 15 групп; все прошли у исполнителя и root.
  Production CGEvent сериализуется и интерпретируется собственным NSTextView;
  финальный системный post подменён, микрофон/TCC/чужие поля не используются.
- Два независимых финальных ревью Spec/Standards одобрили код без blockers,
  Target SHA256 `cf3d4d6e29672b1c9601e0cd4234c9253ee94d3214d45f428a65f9429d351c41`.
  Актуальный статус проверок native/Linux, упаковки, установки и публикации
  1.4.6 ведёт root в `.autopilot/state.js` и
  `.autopilot/2026-08-29-mac-layout-switcher/dictation-completion-qa.md`.
  Ручная диктовка в собственном поле Codex ожидает приёмки; harness не
  подтверждает живую UI-доставку или универсальную совместимость.

## Изменения для 1.4.3 (G20, 08.10.2026)

- Keyboard Target переиспользует DictationAccessibility: bounded lazy AX bootstrap, проверяемый direct/Unicode путь, точное исходное значение/граница слова и каретка. Результат confirmed/untouched/uncertain; попытка записи не повторяется. Setter success и CGEvent.post не являются подтверждением.
- Option захватывает поле заново вне tap; выделение, затем буфер/undo, затем слово перед курсором из свежего AX snapshot. Если слова нет — RU/EN. Deferred Option отменяется при вмешательстве до начала capture. Первый bind не сбрасывает буфер; смена поля/поколения сбрасывает.
- Uncertain блокирует Enter/Tab только текущей очереди. Обычные символы после восстановленной каретки продолжаются; если осталось неизвестное выделение, ввод сохраняется в selectable/scrollable панели. RPC выбора диапазона и восстановления проверяются readback, в том числе timeout-after-apply. Исходник и граница валидируются из того же snapshot, который используется для записи.
- Cold first separator до готовности AX проходит исходным, чтобы не исправлять текст после отправки; следующий Option может восстановить слово из поля. Нет обещания атомарности AX/CG или принятой UI-доставки в Codex.
- Новый tools/test-keyboard-adapter.sh запускает реальный Target/Typist с подставленной AX/CG границей и собственным NSTextView; native build и G19 harnesses проверяются отдельно. Итоговые Linux/release/review доказательства ведёт root.

## Изменения для 1.4.0 (07.10.2026)

- Контекст ввода и отмены сбрасывается при смене поля/приложения, клике и навигации. Перед исправлением проверяется исходный текст и поле; замена одним AXSelectedText не оставляет наполовину удалённое слово. Поддержка зависит от редактируемых AX-атрибутов приложения.
- `ozon` не меняется; `b/B` и `z/Z` исправляются в `и/И` и `я/Я` без обязательного русского контекста, а `plan b` остаётся английским.
- Существующее сочетание конвертации (по умолчанию одиночный Option) сначала исправляет выделение. Регистр, пробелы, переносы, цифры и неизвестные символы сохраняются; буфер обмена и Enter не используются. Без выделения сохраняется проверенная конвертация/откат слова. Недоступное выделение не запускает старый откат; показывается объяснение. Обычная клавиша сочетания подавляется вместе с keyUp.
- Диктовка автоматически проверяет/готовит модель при первом использовании; служебный optimized_cache разрешён. Отмена/ошибка не вызывают бесконечного повторения. После загрузки или разрешения микрофон требует нового удержания сочетания.

## Проверки и ограничения

Linux-тесты: изолированная копия в `/tmp` на `claudebot-server`; Swift — `/home/claudebot/swift-toolchain/swift-6.0.3-RELEASE-ubuntu24.04/usr/bin`. Живые выделение/ввод в сторонних приложениях и микрофон без отдельного запроса не трогать. Текущий командный процесс не имеет Accessibility trust, поэтому положительная AX-приёмка на реальных полях остаётся ручной. Проверить многострочное выделение, кириллицу/латиницу/смешанный текст, смену поля/выделения во время ожидания, неподдерживаемое поле, обычное сочетание keyDown/keyUp, быстрый ввод и отмену подготовки модели.
