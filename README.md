# Mac Layout Switcher Next


Экспериментальный форк [alimp01/mac-layout-switcher-next](https://github.com/alimp01/mac-layout-switcher-next),
основанный на стабильной версии 1.4.12. Next переносит распознавание и перепечатку
Keyboop; локальная диктовка GigaAM v3 сохранена. Исторические проверки версий
1.4.x ниже относятся к stable и **не означают аппаратную приёмку Next**.
Контракт нового ввода описан в [ADR 0014](docs/adr/0014-next-keyboop-transport.md).

## Отдельная установка Next и возврат к stable

- Установите `MacLayoutSwitcherNext.app` рядом с `MacLayoutSwitcher.app`.
  Bundle ID Next — `space.alimp.maclayoutswitcher.next`; в меню, окнах и
  разрешениях он называется **Mac Layout Switcher Next**. Не переименовывайте
  Next в имя стабильного приложения и не заменяйте им stable.
- Перед запуском Next завершите stable через её меню и выключите её автозапуск,
  если собираетесь пользоваться Next при входе. Next не завершает другие процессы.
  При уже запущенной stable он отказывает в запуске перехвата с объяснением.
  Второй Next блокируется общей файловой блокировкой пользователя. Если macOS
  сообщает о запуске stable позже, Next снимает свой перехват и предлагает закрыться.
  Это защита на уведомлениях ОС, а не атомарная блокировка неизменённой stable:
  одновременный запуск обеих программ не поддерживается.
- Next хранит настройки, шаблоны, исключения, счётчики откатов и модель отдельно:
  `~/Library/Application Support/MacLayoutSwitcherNext/`. Автоматического импорта
  из stable нет. GigaAM скачивается и проверяется в каталоге Next; исходная модель
  stable и её кеш не изменяются. Разрешения и автозапуск Next настраиваются отдельно.
- Для возврата завершите Next, выключите его «Запускать при входе» и откройте
  существующий `MacLayoutSwitcher.app`. Настройки stable остаются прежними.
  Обновлятор Next не переключает каналы и не делает откат на stable.
- До повседневного использования проверьте Next в собственном тестовом поле:
  `ghbdtn` + пробел и отдельно Option, Enter/Shift+Enter/Tab, быстрый набор,
  выделение/откат, GigaAM и переходы между приложениями. Сборка и локальные
  harness не подтверждают доставку физических клавиш во все редакторы.

Собственный аналог **Punto Switcher** и **Caramba Switcher** для macOS:
приложение в меню-баре, которое само замечает текст, набранный не в той
раскладке («ghbdtn» вместо «привет»), переключает раскладку и перепечатывает
слово. Плюс исправление выделенного текста или последнего слова по Option, автозамена по шаблонам и звуки
клавиш. Дневника (записи набранного) нет.

## Чем отличается от Punto и Caramba

- **Punto Switcher для Mac (Яндекс)** — заброшен: последняя сборка 2.1.2
  вышла в ноябре 2017 года, проект заморожен и на современных macOS не
  работает.
- **Caramba Switcher (Сергей Москалёв, автор оригинального Punto)** — жива и
  полностью автоматическая, но закрытая и по подписке (~$6/год в Mac App
  Store), с самообучением, но без ручных шаблонов.
- **Mac Layout Switcher Next (этот проект)** — бесплатный и открытый, весь код у
  вас. Автоматика + Option-хоткей для ручной конвертации и отката + автозамена
  по вашим шаблонам + звуки. Без облака, без подписки, без дневника.

## Что умеет Next

- Распознаёт RU/EN по словарям, триграммам и правилам Keyboop, закреплённым
  на `fb9bdde4`. Правильные слова и неоднозначные технические обозначения
  защищаются правилами; уникальные смешанные варианты вроде `привtn` могут
  исправляться. Это эвристика, а не гарантия отсутствия ошибок.
- Исправляет собственное свежее слово после пробела, Enter или Tab без
  обязательного чтения AXValue/выделения. Пакет Backspace + Unicode отправляется
  последовательно; перехваченный разделитель и быстрые следующие клавиши идут
  после него. Shift+Enter сохраняет исходные модификаторы.
- При высокой уверенности исправляет слово после 150 мс без новых клавиш.
  Live-путь ограничен 4–16 символами, не работает после Backspace внутри слова,
  после ручной конвертации до следующей границы, для сниппетов и их префиксов,
  при удерживаемых модификаторах и в Chromium/Electron. Граница слова и Option
  в этих редакторах остаются доступны.
- **Option** конвертирует выделение, иначе откатывает свежую замену или
  конвертирует собственное текущее/последнее слово. Для выделения и ранее
  введённого текста используется проверяемый AX-путь. Недоступный AX не мешает
  собственному свежему буферу; без кандидата Option переключает RU/EN.
  После заданного числа откатов слово становится исключением (по умолчанию 3).
- Клик, навигация, смена приложения, пауза, SecureInput, запись хоткея и
  прерывание tap сбрасывают контекст и отменяют ещё не начатую замену.
  Буфер ограничен 64 символами; переполнение отключает замену до следующей
  границы. Приложения-исключения по умолчанию: Terminal, iTerm2, VS Code.
- Сохраняет сниппеты, звуки исправления/отката и локальную диктовку GigaAM v3.
  Обычные клавиши не озвучиваются. Автоматического доступа к clipboard нет.

## Совместимость клавиатурного ввода Next

Свежий буфер перепечатывается глобальными событиями HID, включая маршрут,
нужный неактивирующим окнам вроде Spotlight. До первого Backspace создаётся
весь пакет событий; Unicode делится на порции до 12 UTF-16 единиц без разрыва
surrogate pair. Удерживаемые Shift/Option/Cmd/Ctrl задерживают начало не более
400 мс: если они не отпущены, исходное слово сохраняется, физический разделитель
досылается при сохранённом контексте.

**Отправка событий не подтверждает изменение текста.** Без AX приложение не
может доказать точное поле, доставку каждого события или результат. Оно проверяет
поколение контекста, приложение, SecureInput и модификаторы, но между проверкой
и обработкой события редактором остаётся системная гонка. Программная смена
поля без доступного AX также может быть незаметна. После начавшегося удаления
автоматического повтора нет. При обнаруженном прерывании исходник, планируемая
замена и удержанный ввод сохраняются в панели; Enter/Tab этой очереди не уходят.

Выделение, ранее введённое слово и диктовка сохраняют проверки AX поля,
исходного текста, диапазона и результата. Для Safari/Chromium/Electron этот
путь выбирает проверяемый Unicode до записи при неподходящем AXSelectedText.
Недоступное поле не переводит диктовку или произвольное выделение на слепое
удаление. Clipboard автоматически не используется ни одним из путей.

Нативные fixtures проверяют production Engine/EventTap/Typist через настоящие
CGEvent/NSEvent и собственные скрытые NSTextView. Конечный системный post
заменяется доставкой в эти поля: это проверка поведения, не аппаратная приёмка
WindowServer, Spotlight, Safari или каждого редактора.

### История исправлений стабильной версии 1.4.x

Следующие результаты относятся к родительскому приложению и его AX-пути.
Они не подтверждают аппаратную совместимость нового buffered-пути Next.

В 1.4.5 замена ждёт подтверждения выделения до вставки. Chromium может
подтвердить запрос Accessibility раньше, чем применит его: прежняя версия
считала старую каретку признаком отсутствия изменений и возвращала пробел
в редактор, где он удалял уже выделенное слово. Теперь неподтверждённый запрос
выделения или восстановления каретки удерживает разделитель и последующий
ввод в панели вместе с исходником и полной заменой. Уже выделенный исходник
не вызывает повторного запроса того же диапазона.

Опубликованная 1.4.5 установлена и проверена физическими клавишами
в двух собственных полях Codex IAB: contenteditable и textarea. В обоих случаях
`срфе` в русской раскладке + пробел → `chat `; исходник до пробела и результат
подтверждены DOM-логом и пользователем. Основной composer Codex, аппаратные
Enter/Shift+Enter и остальные приложения пока не прошли отдельную приёмку.

Первое связывание с полем больше не очищает уже набранное слово. Пока ленивое
AX-дерево ещё не готово, очень быстрый первый разделитель может пройти без
исправления; последующий Option заново захватывает текущее/последнее слово.
Недоступное поле не разрешает слепую перезапись. AX и CGEvent не образуют
единую транзакцию: остаётся узкое окно внешнего изменения после проверки.

`tools/test-keyboard-adapter.sh` проверяет production AX-адаптер и очередь
Typist на собственном NSTextView с подставленной системной границей: no-op,
частичную запись, неверный диапазон/префикс, cold bind, Shift+Enter и быстрый
ввод. Локальный harness не подтверждает доставку в установленный Codex;
аппаратная проверка установленной 1.4.5 описана выше.

В 1.4.4 при неподтверждённой замене панель
сохраняет точный исходный фрагмент и всю планируемую замену вместе с удержанным
вводом до явного «Закрыть». Это действует для автоматической замены, Option,
сниппетов/отката и диктовки поверх выделенного текста. После возможного удаления
или частичной вставки автоматического восстановления/повтора в поле нет.
Найден и исправлен воспроизводимый путь удаления: автоповтор пробела/Enter
во время временного выделения слова проходил в редактор раньше замены и мог
заменить исходник одним разделителем. Теперь повторы печатных клавиш, Backspace
и разделителей ждут окончания замены в общей очереди; команды, клик и навигация
по-прежнему отменяют её. Подавленный исходный разделитель также подавляет свой
keyUp. Это исправление конкретной гонки; все случаи пользовательской жалобы в
установленных приложениях пока не проверены.

`tools/test-keyboard-engine.sh` воспроизводит старое удаление и проверяет новый
порядок через реальные EventTap/KeyTranslator/Engine на частном NSTextView.
Ввод в неверной раскладке проверяется до разделителя. Системная AX-граница и
финальная доставка подставлены; разрешение обычных клавиш в NSEvent моделирует
отсутствующий WindowServer. Ограничения и baseline red-команда описаны в
`tools/keyboard-harness/README.md`.

`tools/test-keyboard-selection-delay.sh` проверяет настоящий Target/Typist и
SelectionConverter с отложенным применением AX-запроса на собственном
NSTextView: Space/Enter/Shift+Enter/Tab, быстрый следующий символ, отмену,
восстановление каретки и преобразование уже выделенного текста. Та же проверка
на прежних исходниках воспроизводит удаление:
`MLS_SELECTION_BASE_REF=c0be78e bash tools/test-keyboard-selection-delay.sh`.
Каждый запуск сохраняет копии исходников, SHA256 и результат в `/tmp`.
Финальная доставка здесь локальная; аппаратная проверка установленного
1.4.5 в Codex описана выше и проводится отдельно от этого harness.

`tools/test-keyboard-webkit.sh` воспроизводит no-op на настоящем AX wrapper
системного WebKit и проверяет исправление `шднф` → `ilya ` на собственном
невидимом WebView. Проверяются Enter/Shift+Enter/Tab после замены, Option,
соседний текст/emoji, быстрый ввод, readonly, отмена и сохранение полного
результата при неподтверждённой доставке. Исходная ошибка воспроизводится той же
проверкой: `MLS_WEBKIT_BASE_REF=ef8be979 bash tools/test-keyboard-webkit.sh`.
Подставлены сведения о процессе и финальная доставка в собственный WebHTMLView;
это локальная интерпретация событий, не аппаратная доставка в Safari.

Нативный harness дополнительно проверяет настоящие CGEvent production-транспорта,
их Unicode-пayload, сериализацию и `NSTextView.keyDown`: кириллицу, регистр,
emoji, переносы, длинный текст, каретку и хвост поля. Только финальный процессный
post подставлен; это не проверка WindowServer или установленного Codex.

## Покрытие слов и неоднозначность

В 1.4.1 добавлен проверенный набор из 41 повседневного русского слова,
включая `ни`, `буду`, `могу`, `когда`, `пусть`, `люблю`, без снижения общих
порогов детектора. `rfr?`, `ghbdtn!`, `(yt)!`, `((yt))` распознаются с
сохранением внешних `!?` и круглых скобок. Поддерживаются вложенные круглые
скобки вокруг слова и затем конечная последовательность `!?`; внутренняя
пунктуация вроде `(yt!)` остаётся без изменения. Запятые, точки, кавычки и
квадратные скобки не обрезаются: это физические русские буквы
(`cgfcb,j` → `спасибо`, `K><K>` → `ЛЮБЛЮ`).

У `ns`↔`ты`, `jq`↔`ой`, `herb`↔`руки`, `tv`↔`ем`, `ev`↔`ум`, `BLE`↔`иду`
обе стороны осмысленны. В начале ввода они сохраняются, затем решение
зависит от языка предыдущего слова. Ранее `ns` и `jq` исправлялись без
контекста; теперь защищены и эти английские обозначения. Прежнее предпочтение
русского для `jr`→`ок`, `ye`→`ну`, `tot`→`еще` сохранено. Автоматика не может
определить намерение во всех таких случаях; остаются Option и исключения.

Исключение для `ghbdtn` защищает также `(GHBDTN)!`. Обучение откатом сохраняет
исходный токен целиком: отмена `(Rfr)!` учит исключение для `(rfr)!`, а не для
всех вариантов `rfr`. Формат исключений прежний, регистр не учитывается.
Проверки используют независимые буквальные примеры через публичное ядро;
это регрессионный набор, а не оценка точности на реальном корпусе.

## Требования

- macOS 13 (Ventura) или новее, Intel или Apple Silicon.
- Swift toolchain — Xcode Command Line Tools:

  ```sh
  xcode-select --install
  ```

## Сборка

Одной командой из корня репозитория (на своём Mac):

```sh
./build.sh
```

Скрипт соберёт релиз через SwiftPM, разложит `dist/MacLayoutSwitcherNext.app`
(с `LSUIElement` — без иконки в Dock) и подпишет его ad-hoc. В конце напечатает
путь и дальнейшие шаги.

Иконка приложения: исходник — `Resources/AppIcon.svg`, готовый
`Resources/AppIcon.icns` лежит в репозитории и попадает в бандл автоматически;
после правки SVG пересобрать его командой `python3 tools/make-icns.py`
(нужен `cairosvg`).

Логику детектора можно проверить ещё до сборки .app — на любой машине,
включая Linux (это же гоняет CI сборки):

```sh
swift test
```

## Установка через .dmg

Чтобы получить приложение как полноценный дистрибутив — образ, который
монтируется и ставится перетаскиванием в «Программы», — соберите `.dmg`
(на своём Mac, одной командой):

```sh
./build-dmg.sh
```

Скрипт сначала соберёт `dist/MacLayoutSwitcherNext.app` через `./build.sh` (если
его ещё нет; `--rebuild` пересобирает принудительно), затем упакует его в
`dist/MacLayoutSwitcherNext.dmg` с ярлыком «Программы» (Applications) внутри.

Дальше:

1. `open dist/MacLayoutSwitcherNext.dmg` — смонтировать образ.
2. Перетащить **MacLayoutSwitcherNext.app** на ярлык **«Программы»** (Applications).

Приложение подписано только ad-hoc (нет Apple Developer ID, нет нотаризации —
это личная сборка), поэтому **первый запуск** после установки:

- В «Программах» **правый клик по MacLayoutSwitcherNext → «Открыть»** → в диалоге
  Gatekeeper подтвердить «Открыть» (обычный двойной клик macOS может отклонить).
  Это нужно один раз; дальше приложение запускается как обычно.
- Затем выдать те же два разрешения, что и для .app —
  **Универсальный доступ (Accessibility)** и **Мониторинг ввода (Input
  Monitoring)** — см. раздел «Первый запуск и разрешения» ниже.

## Первый запуск и разрешения

1. Запустить: `open dist/MacLayoutSwitcherNext.app`. Из-за ad-hoc подписи
   Gatekeeper может отказать при двойном клике — тогда **правый клик по .app →
   «Открыть»** (один раз).
2. Приложение слушает клавиатуру во всех программах, поэтому macOS требует два
   разрешения. Приложение покажет подсказку с кнопками; выдать вручную можно
   так:
   **Системные настройки → Конфиденциальность и безопасность →**
   - **Универсальный доступ (Accessibility)** — включить «Mac Layout Switcher Next».
   - **Мониторинг ввода (Input Monitoring)** — включить «Mac Layout Switcher Next».
3. Перезапустить приложение (пункт меню-бара «Я выдал разрешения» или заново
   `open`). В меню-баре появится индикатор раскладки («RU»/«EN»).

## Меню-бар

В самом меню-баре приложение показывает **текущую раскладку** текстом —
жирное **RU** или **EN** (неопознанный источник, например IME, — «--»).
Индикатор меняется сразу при любой смене раскладки: сами переключились
(⌃Space, меню ввода), сработало авто-исправление или Option-конвертация.
Обновление событийное (системное уведомление смены источника ввода), без
поллинга. В паузе индикатор приглушён: серый, с префиксом «⏸».

Пункты меню:

- **Пауза / Работа** — временно выключить перехват (индикатор приглушается).
- **Автопереключение** — вкл/выкл авто-исправление по детектору.
- **Звуки** — вкл/выкл озвучку.
- **Запускать при входе** — автозапуск после перезагрузки Mac (см. ниже).
- **Открыть snippets.json / config.json** — правка шаблонов и настроек во
  внешнем редакторе (после правки Engine перечитывает файлы).
- **Горячие клавиши…** — окно настройки горячих клавиш (см. ниже).
- **Проверить обновления…** — ручная проверка новой версии (см. «Автообновление»).
- **О программе**, **Выход**.

Все тумблеры пишутся в `config.json` сразу и переживают перезапуск.

## Горячие клавиши

Пункт меню-бара **«Горячие клавиши…»** открывает настройки сочетаний:

- **Конвертация / откат** — клавиша исправления выделения RU↔EN, последнего
  слова и отката автоисправления. По умолчанию **Option** (одиночный tap) — как было раньше.
- **Вкл/выкл авто** — клавиша, включающая/выключающая автопереключение. По
  умолчанию **не назначена**.
- **Диктовка** — удерживайте ⌃⌥Space для записи; отпускание завершает запись.

Для конвертации выделение должно быть доступно и изменяемо через Accessibility.
Защищённое или неподдерживаемое поле не меняется; приложение показывает объяснение.
Изменение фокуса/выделения или новый ввод отменяют ожидающую конвертацию. Переносы
строк вставляются как текст, без Enter. Для смешанного текста наличие русских букв
выбирает направление в EN; иначе — в RU. Пунктуационные клавиши карты (`;`, `[`,
`,` и другие) преобразуются по физической раскладке. Обычная клавиша сочетания
конвертации подавляется вместе с отпусканием, поэтому не печатается в поле.

У каждой строки — текущее значение, кнопка **«Записать»** (нажмите нужное
сочетание — одиночный модификатор вроде Option/Caps Lock или клавишу с
модификаторами, например ⌘⇧K; **Esc** отменяет запись) и **«Сброс»** (вернуть
значение по умолчанию).

Выбор сохраняется в `config.json` (поля `convertHotkey` / `toggleAutoHotkey`) и
применяется сразу; для надёжности после смены можно перезапустить приложение.
Старый `config.json` без этих полей грузится с дефолтами — обновление ничего не
ломает.

## Автозапуск при входе

Пункт меню-бара **«Запускать при входе»** включает автостарт приложения после
перезагрузки Mac (входа в систему). По умолчанию **выключено**. Галочка
показывает **фактическое** состояние: под капотом — `SMAppService.mainApp`
(macOS 13+), поэтому источник истины — сама система, а не `config.json`.

- Если регистрация не удалась (macOS отказала) — галочка возвращается в прежнее
  положение, ложного «включено» не будет.
- На современных macOS система может попросить **подтвердить автозапуск вручную**:
  при включении появится подсказка и откроется панель **Объекты входа** —
  включите там «Mac Layout Switcher Next», иначе автостарт не заработает (это не
  ошибка, а штатное подтверждение).
- Отключить автозапуск можно и вне приложения: **Системные настройки → Основные →
  Объекты входа**, там же он появится под именем приложения. Если вы сняли его
  там, приложение при следующем старте это заметит и снимет галочку.
- Замечание про ad-hoc-подпись: у неподписанной сборки объект входа в Системных
  настройках может отображаться как «Программа» без внятного имени — это нормально
  для личной сборки без нотаризации.

## Автообновление

Приложение само следит за новыми версиями (репозиторий публичный, версия —
файл `VERSION` в корне **alimp01/mac-layout-switcher-next**, semver):

- **Как проверяет.** Через ~1 минуту после запуска и дальше раз в 24 часа
  приложение сравнивает свою версию (из `Info.plist`, туда её кладёт
  `build.sh` из файла `VERSION`) с raw `VERSION` из ветки `main` на GitHub.
  Есть новее — алерт «Доступна версия X. Обновить?» с кнопками
  **Обновить / Позже**. Нет новее или нет сети — молчит (сетевые сбои видны
  только в системном логе). Пункт меню **«Проверить обновления…»** делает то
  же самое вручную и, в отличие от фоновой проверки, отвечает и
  «Версия актуальна».
- **Как обновляется.** По кнопке «Обновить» приложение запускает скрипт
  `self-update.sh` (лежит в `Contents/Resources` бандла; выполняется его копия
  из временной папки) и выходит. Скрипт скачивает `main.tar.gz` с GitHub,
  собирает `./build.sh` **во временной папке**, и только после успешной
  сборки проверяет bundle ID Next, исполняемый файл, тип приложения, новую
  числовую версию `X.Y.Z` (строго выше текущей) и целостность ad-hoc подписи.
  Та же проверка identity выполняется для установленного приложения **до**
  скачивания. Чужой bundle, stable или понижение версии отклоняются.
  Затем обновлятор ждёт завершения прежнего Next и заменяет `.app` по прежнему
  пути. При сбое установки/запуска он восстанавливает сохранённый Next; если
  восстановление не удалось, отчёт содержит путь к резервной копии. Принятая
  macOS команда запуска сама по себе ещё не подтверждает работающий процесс.
- **Лог**: весь ход обновления — в
  `~/Library/Logs/MacLayoutSwitcherNext-update.log` (загляните туда, если после
  «Обновить» приложение не вернулось за пару минут).
- **Разрешения придётся выдать заново.** Замена `.app` с ad-hoc-подписью
  сбрасывает доверие TCC: при первом старте новой версии macOS снова попросит
  **Универсальный доступ** и **Мониторинг ввода** — сработает обычный
  онбординг. Это плата за обновление без сертификата разработчика; алерт
  обновления предупреждает об этом заранее.

## Локальный backend диктовки (GigaAM v3)

Нативный движок GigaAM v3 E2E RNNT входит в arm64-сборку приложения.
Для диктовки нужны Apple Silicon и macOS **13.4+**. На Intel и macOS
13.0–13.3 функции переключения раскладки работают, диктовка недоступна.
Python, Homebrew и сервер распознавания не нужны.

В 1.4.2 результат при отказе автовставки виден, выделяется и прокручивается.
«Копировать» копирует показанный текст только по явному клику. Сообщения
различают отсутствие Accessibility, недоступное поле/выделение, вмешательство
пользователя и неподтверждённую вставку. Буфер обмена автоматически не меняется.

Перед записью сохраняются конкретное AX-поле, выделение и его значение.
Клавиша, клик, смена приложения/поля или выделения отменяют разрешение вставки
до конца этой попытки, даже после возврата в исходное поле. Esc и пауза отменяют
диктовку. Недоступное выделение не подменяется нулевым положением курсора.
Для ленивого дерева Electron есть ограниченная повторная проверка после
[AXManualAccessibility](https://www.electronjs.org/docs/latest/tutorial/accessibility).

Поддерживаемые редакторы получают одну адресную замену AXSelectedText с
проверкой результата. Для распознанных Chromium/Electron (включая приложение
Codex с Codex Framework) и редакторов без такого setter доступен Unicode-путь:
только доказуемо редактируемое поле с исходным AX-значением/выделением и
наблюдением изменений, порции до 16 UTF-16 единиц без разрыва surrogate pair,
проверка точного значения и курсора после каждой порции. Enter/Tab не посылаются,
полное AXValue не перезаписывается. Сам CGEvent.post не означает доставку.
Неоднозначная/частичная запись не повторяется: весь результат остаётся в панели
с предупреждением проверить поле перед ручным копированием.

AX и доставка клавиш не являются общей транзакцией: остаётся узкое окно
изменения поля между последней проверкой и доставкой. Уведомления AX не содержат
истории старого/нового выделения и могут повторяться или объединяться. В 1.4.6
собственные уведомления проверяются по конкретному полю, значению и диапазону
текущей записи, а не по количеству уведомлений. Раздельная публикация значения
и каретки допускает ограниченное ожидание только известных состояний этой
записи; после подтверждения новые проверки используют точное итоговое состояние.
Для уже начавшегося AX-чтения сохраняются известные состояния порций,
прошедших во время этого чтения. Этот временный список содержит не более
16 наборов: при заполнении очередь вставки ждёт завершения чтения до 0,6 секунды,
а ввод/смена фокуса сразу прекращают ожидание. Завершившееся чтение очищает свой
список; зависшее AX-чтение даёт неподтверждённый результат без повторной записи.
После ожидания точное поле, значение, каретка и разрешение проверяются заново
непосредственно перед записью; замеченное изменение отменяет следующую порцию.
Чужое значение/выделение, физический ввод и смена фокуса отменяют продолжение.
Возврат уже замеченного чужого состояния не восстанавливает разрешение.
Изменение и возврат между системными снимками могут остаться незаметными;
это ограничение AX, а не гарантия атомарной вставки.
Неподдерживаемое наблюдение или непроверяемое поле дают результат для копирования.

Регрессии macOS: `./tools/test-dictation-panel.sh` проверяет production-панель
(реальные размеры, glyph layout, длинный текст, выбор, отсутствие активации и
изменения clipboard). `./tools/test-dictation-adapter.sh` исполняет production
capture/insert через подставной AX-интерфейс и собственный NSTextView: lazy tree,
диапазоны, Unicode, отмена, частичная/неподтверждённая доставка, отсутствие retry.
`bash tools/test-dictation-completion.sh` проверяет полную фразу, длинный Unicode,
повторные/объединённые/задержанные уведомления, раздельный readback значения и
каретки, отмену при чужих изменениях и отсутствие повторной доставки. Набор
включает конкурентные уведомления: сохранённое чужое значение или
выделение отменяет вставку даже после восстановления поля и подтверждения
порции; поздний собственный снимок предыдущей/следующей порции не отменяет её.
Отдельный прогон — `MLS_DICTATION_CASE=race` и `MLS_DICTATION_RACE_KIND` со
значениями `foreign-value`, `foreign-range`, `previous-own`, `next-own`.
`MLS_DICTATION_CASE=multi-own` проверяет собственный снимок через несколько
порций; `MLS_DICTATION_MULTI_KIND` выбирает `four`, `capacity`, `stalled`,
`cancel`, `focus`, `cleanup`, `mutate-value`, `mutate-range`, `mutate-field` или
`mutate-secure`. Обычный прогон включает все 15 групп, включая изменение поля
во время ожидания и проверку отсутствия следующей записи после него.
Тот же runner с `MLS_DICTATION_BASE_REF=438c8be` воспроизводит усечение до
`Давай проверим, ` на исходном коде. Он использует production Target/Permit,
Unicode CGEvent с сериализацией и собственный NSTextView; системная отправка
подменена. Причина именно уведомлений в реальном Codex пока не подтверждена.
Имитация доставки в harness не является живой приёмкой чужого Codex/contenteditable.
Командный процесс не имеет AX trust; такая приёмка остаётся ручной.
Актуальные результаты ревью, проверок и публикации 1.4.6 находятся в
`.autopilot/state.js` и
`.autopilot/2026-08-29-mac-layout-switcher/dictation-completion-qa.md`.
Ручная диктовка в собственном поле Codex ещё ожидает приёмки.

При первом открытии диктовки или использовании сочетания приложение само
проверяет модель и при необходимости загружает **233 МБ** весов (232 576 763 байта).
Повторного вопроса «Загрузить» нет; прогресс и отмена доступны. Каждый файл
проверяется по размеру и SHA256; служебный `optimized_cache` не делает
исправную модель повреждённой. Ошибка и отмена не запускают бесконечный повтор.
После загрузки или выдачи разрешения нужно заново удержать сочетание: микрофон
сам не включается. При отмене временная загрузка удаляется.
Веса хранятся отдельно от .app в
`~/Library/Application Support/MacLayoutSwitcherNext/SpeechModels/` и переживают
обновление приложения. После загрузки распознавание полностью офлайн.
Запись не отправляется на сервер, аудио и текст не пишутся в логи.

`./build.sh` на Apple Silicon разрешает точную SwiftPM-зависимость
[GigaSTT 2.17.0](https://github.com/ekhodzitsky/gigastt-swift/tree/v2.17.0)
и скачивает проверяемый SwiftPM XCFramework (~78 МБ) при первой сборке.
Готовая .app включает подписанный `Contents/Helpers/SpeechRecognizer`,
`Contents/Resources/Licenses` и все ресурсные SwiftPM `.bundle` (включая языковые данные). Linux и Intel не скачивают этот binary target.
Для cross-сборки Intel на arm64-хосте отключите helper явно:
`MLS_DISABLE_SPEECH=1 swift build --triple x86_64-apple-macosx13.0`.
Обычная сборка arm64: `swift build` или `./build.sh`.
Каталог вывода .app/.dmg можно задать через `MLS_DIST_DIR=/path/to/output ./build.sh`
или `MLS_DIST_DIR=/path/to/output ./build-dmg.sh --rebuild`.
Для подписи выбирайте локальный каталог вне синхронизируемого iCloud Documents:
FileProvider может добавлять FinderInfo к .app уже после подписи.

Для диагностики готового backend (WAV должен находиться в текущем каталоге):

```sh
/path/to/MacLayoutSwitcherNext.app/Contents/Helpers/SpeechRecognizer \
  "$HOME/Library/Application Support/MacLayoutSwitcherNext/SpeechModels/gigaam-v3-e2e-2026-06-22" \
  recording.wav
```

Helper возвращает JSON с `text` и код 0 либо JSON с `error` и ненулевой код.
Тишина — `no_speech`, отсутствующая/нечитаемая модель — `model_load_failed`.
Приложение запускает его в приватной рабочей папке, ограничивает время и
объём ответа, завершает процесс при отмене и удаляет временную копию WAV.
Длинные записи обрабатываются окнами движка без обрезки после 25 секунд.
Технические решения и фактическая проверка описаны в
[ADR 0012](docs/adr/0012-local-gigaam-helper.md).

## Проверки идентичности и обновления Next

```sh
./tools/test-next-identity.sh
python3 tools/lifecycle-harness/update.py
bash -n build.sh build-dmg.sh tools/self-update.sh
```

Нативная проверка использует собственный временный каталог и настоящий `flock`,
подставляет список приложений и не создаёт глобальный перехват или видимые окна.
Проверка упаковки запускает production scripts с контролируемыми границами
компилятора, подписи и DMG; это не проверка настоящей подписи/смонтированного образа.
Updater fixture проверяет отказ от чужого канала, старой версии, повреждённой подписи,
сбои сети/сборки/копирования/замены/запуска и сохранение прежнего Next при откате.
Релиз отдельно требует полной speech-сборки и проверки смонтированного DMG.
